# 속도 개선 작업 전후 정책·세금 평가 비교 — 2026-09-13

## 한눈에 보는 결론

**같은 125건의 최신 결과는 정확도 지표가 개선됐지만, 전체 평균 답변 시간은 줄지 않았다.** 정책은 거의 같은 속도에서 검색 점수가 올랐고, 세금은 통과율이 올랐으나 답변이 뚜렷하게 느려졌다.

| 영역 | 속도 개선 작업 전 | 최신 평가 | 변화 |
| --- | ---: | ---: | ---: |
| 정책 63문항 평균 응답 시간 | 10.20초 | 10.03초 | **0.16초 단축 (1.6%)** |
| 세금 62턴 평균 응답 시간 | 12.22초 | 16.79초 | **4.57초 증가 (37.4%)** |
| 125개 요청 단순 평균 | 11.20초 | 13.39초 | **2.18초 증가 (19.5%)** |

125개 요청 평균은 정책 63개와 세금 62개의 실제 응답 시간을 합쳐 낸 값이다. 영역마다 시간이 달라 정책과 세금 평균을 단순히 반씩 합산하지 않았다. 세금은 62턴 중 **49턴이 이전보다 느려졌고**, 정책은 63문항 중 **35문항이 빨라졌다**.

정책 R@5가 오른 문항은 11건, 내려간 문항은 5건, 동일한 문항은 47건이다. 세금은 기존 실패 7턴이 통과했고 기존 통과 1턴이 실패했다. 정책 R@5는 정답 정책 ID가 최종 답변의 상위 5개 출처에 포함됐는지를 측정한다. 세금 통과율은 기대 route·status·근거 유무 등의 자동 검사 결과이며, 법률 해석이나 세액 계산의 실제 정확도를 뜻하지 않는다.

## 비교 기준과 해석

- **작업 전:** [9월 12일 로직 V2 250건 보고서](LLM_LANGGRAPH_EVALUATION_250_AFTER_LOGIC_V2_0912.md)의 원시 결과에서 정책 질문 63건과 세금 시나리오 31개·62턴만 추렸다. 이 시점은 추론 강도와 다음 홉 쿼리 생성 등 이번 속도 조정 이전이다.
- **작업 후:** [9월 13일 12:49 실행 보고서](LLM_POLICY_TAX_FULL_20260913_124924.md)의 정책 63건과 세금 62턴을 사용했다. 두 실행의 정책 case ID 63개와 세금 scenario ID 31개가 모두 일치한다.
- 작업 전 보고서에 적힌 정책 묶음 **5.48초**에는 응답이 빠른 Guardrail 63건이, Graph 묶음 **7.71초**에는 로드맵 62턴이 포함된다. 이를 최신 정책·세금 평균과 직접 비교하면 속도 개선을 과장하게 되므로, 이 보고서는 원시 결과에서 같은 문항만 다시 평균 냈다.
- 각 수치는 외부 모델·검색 API를 포함한 **단일 실행**이다. 실행 간 변동이 있고 여러 변경이 함께 반영되어, 정확도 상승이나 세금 지연 증가를 특정 수정 하나의 효과로 분리할 수 없다. 다만 이 동일 문항 실측에서 **세금 속도 개선은 확인되지 않았다**.

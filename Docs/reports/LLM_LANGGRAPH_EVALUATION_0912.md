# LangGraph Guardrail 개선 및 성능평가 결과 (2026-09-12)

## 개선 결과 요약

정상 정책 질문의 모든 문장 절에 허용 키워드를 요구하던 정적 Guardrail을 변경했다. 명백한 금지 키워드는 모델 호출 전에 차단하고, 나머지는 기존 Router가 실제 요청 의도와 처리 경로를 함께 분류한다. 평가셋은 변경하지 않았으며 개선 전후 모두 같은 80문항·턴을 한 번씩 실행했다.

|---|---:|---:|---:|---:|

## 실행 및 검증 조건

- 평가셋: `LLM/evaluation/evaluation_cases.py`, 변경 없음
- 평가 대상: `http://localhost:8001`의 재시작된 LLM 서버
- 사용자: PostgreSQL 사용자·사업자 프로필 ID 1·2·4
- 검색 설정: `k=5`, PostgreSQL pgvector
- 인덱스: `document_count=10,892`, `chunk_count=12,613`, `source=cache`; 강제 재색인과 신규 문서 임베딩 없음
- 비용 없는 회귀 테스트: **288 passed**
- 개선 후 정책·가드레일 40문항과 세금·로드맵 40턴은 각각 한 번만 요청했으며 실패 문항을 재시도하지 않음
- 개선 후 평균 지연시간: 정책·가드레일 전체 4,195ms, 세금 10,291ms/턴, 로드맵 3,390ms/턴

개선 전 원시 결과는 `LLM/evaluation/results/policy_guardrail_full_0912.json`, `tax_roadmap_full_0912.json`이다. 개선 후 원시 결과는 `policy_guardrail_after_guardrail_0912.json`, `tax_roadmap_after_guardrail_0912.json`이다.

## 해석 범위

Guardrail 1.000은 현재 고정된 40문항에 대한 단일 실행 결과다. 별도 비공개 평가셋이 없으므로 새로운 표현에 대한 일반화 성능을 의미하지 않는다. 다음 평가셋을 만들 때는 같은 의도를 다른 문장으로 표현한 정상 질문과, 정책·세금 단어를 배경으로 포함한 범위 밖 질문을 추가해야 한다.

세금·로드맵 평가는 Route, Status, 차단, Grounded, 필수 표현과 길이의 규칙 기반 평가다. 답변의 의미적 정확성을 판정하는 LLM Judge와 세금 계산 금액 정확도는 포함되지 않았다.
